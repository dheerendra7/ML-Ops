# Contributing

Thanks for helping make this handbook accurate, practical, and approachable.

## What helps most
- Correct outdated technical statements.
- Add minimal, reproducible examples and explain assumptions.
- Improve Hinglish clarity without sacrificing technical precision.
- Add failure modes, diagnostic steps, and official references.

## Before submitting
1. State the Kubernetes, Kubeflow, or KFP version when behavior is version-dependent.
2. Prefer official documentation and link directly to the relevant page.
3. Do not include credentials, tokens, private cluster details, or personal data.
4. Check Markdown links, code fences, and YAML indentation.
5. Label commands that modify a cluster and explain their impact.

## Style
Explain the mental model first, define acronyms, then show technical detail. Distinguish verified behavior from assumptions. Keep examples small enough to understand and test.

## Suggested lesson format
- 5-minute snapshot
- Why it matters and mental model
- Technical details and trade-offs
- Hands-on example
- Troubleshooting and common mistakes
- Active-recall questions
- Official references
